## Planning Contract

### Key Technical Decisions

- KTD1. **Packages follow the architecture's section 4, and `transport/connect` serves both services.** `internal/protocol` holds the runner protocol's messages and its one Go interface. `internal/api` holds the client API's messages, its Go interface and the client-side follower. `internal/engine` exposes two small types over one core, one implementing each interface, so the two services' method names never collide, and declares the store and log interfaces it uses. `internal/transport/connect` adapts both services to HTTP, as server handlers and as clients. `internal/store/logs` keeps logs on disk. `internal/runner` loops on the protocol. `cmd/crew-actions` reads flags and the environment, wires the pieces and prints. The connect-go rule holds unchanged, since its `connectrpc.com/connect` prefix already covers `connectrpc.com/connect/v2` and its subpackages. Rejected: plain HTTP with JSON in `internal/api`, which would give one engine two transports and two error vocabularies.
- KTD4. **Errors cross HTTP as a small vocabulary of `internal/model` sentinels.** The engine returns `ErrConflict`, `ErrNotFound`, a new `ErrInvalid`, which wraps a message that is safe to show, or a new `ErrUnavailable` when it is stopping. `transport/connect` maps them to `Aborted`, `NotFound`, `InvalidArgument` and `Unavailable`, and back. A request over the size limit (`ResourceExhausted`) comes back as `ErrInvalid`. A non-remote error, such as a refused connection or a stream cut by a dying server, also comes back as `ErrUnavailable`. Any other error reaches the client as `Unknown` with no message, so internal detail never leaks. When the caller's own context is done, the client returns the context's error, never `ErrUnavailable`, so a Ctrl-C is never retried. The runner and `run` branch on these sentinels with `errors.Is` and never see a connect code.
- KTD11. **The engine checks the socket it bound, the request's origin and Host, and the request size.** Loopback keeps out the network, not other local users or processes, and the engine says so on its first line of output.
  - It listens first and refuses unless the bound address is loopback, which also catches `:7700` and a `localhost` mapped elsewhere. It does this before it opens the database.
  - The handler is wrapped in the standard library's `http.CrossOriginProtection`, so a browser page cannot call it cross-origin. The Go clients send no `Origin` header.
  - A request whose Host, port split off, is not `localhost` (any case) or a loopback IP gets 403, which closes DNS rebinding. An empty Host is refused.
  - Requests are capped at 1 MiB.
  - The server sets `ReadHeaderTimeout` and no `WriteTimeout`, which would cut streams.

## Implementation Units

### U8. Connect transport

**Goal:** both services are served over HTTP on loopback and reached by clients that speak `internal/model`'s sentinels.

**Requirements:** R1, R2, R3; KTD1, KTD4, KTD11.

**Dependencies:** U2, U5.

**Files:**
- Create `internal/transport/connect/server.go`, `internal/transport/connect/client.go` and `internal/transport/connect/errors.go`.
- Create `internal/transport/connect/server_test.go` and `internal/transport/connect/client_test.go`.

**Approach:**
- The server is a `http.Handler` that mounts both services with a 1 MiB read limit, behind `http.CrossOriginProtection` and a Host check (KTD11).
- The clients implement `protocol.Engine` and `api.Builds` over a base URL with an `http.Client` that has no timeout.
- `errors.go` holds both directions of KTD4's mapping. The follow client turns a stream that ends without the build's end into `ErrUnavailable`.

**Patterns to follow:** `httptest.NewServer` with a fake `protocol.Engine` and `api.Builds` in the test file.

**Test scenarios:**
- Each call of both services round-trips its fields through a fake.
- `ErrInvalid` with a message reaches the client as `ErrInvalid` with the same message. `ErrConflict` and `ErrNotFound` round-trip.
- A `Follow` whose fake returns `ErrUnavailable` mid-stream reaches the client as `ErrUnavailable`.
- A plain error from the fake reaches the client with no message and matches none of the sentinels.
- A 2 MiB submit reaches the client as `ErrInvalid`.
- A request with Host `evil.example`, `localhost.evil.example`, `127.0.0.1.nip.io` or `0.0.0.0:7700`, or with no Host, gets 403. `localhost:7700`, `LOCALHOST:7700`, `127.0.0.1:7700` and `[::1]:7700` pass.
- A request with Host `127.0.0.1:7700` and `Origin: https://evil.example` gets 403, and the fake sees nothing.
- A POST to `Submit` with `Content-Type: text/plain` gets 415, and a GET to any method is refused.
- A client whose context is cancelled mid-call gets the context's error, not `ErrUnavailable`.
- A client against a closed server gets `ErrUnavailable`. A follow stream whose server closes mid-stream gets `ErrUnavailable`.

**Verification:** the scenarios pass, and connect-go is imported only under `internal/transport/connect`.
