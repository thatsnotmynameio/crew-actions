## Product Contract

### Summary

`fromConnect` maps to `ErrUnavailable` only what means the engine is gone; other non-remote errors become server errors that `next` and `run` do not retry.

### Context

Part 6's runner retries every call about an attempt while the engine is unreachable, so "unreachable" must mean only that. This part builds some of R17, which part 6 completes.

### Key Decisions

- **An engine that starts gives every running lease one more period before reaping.** A lease that expired while the engine was down does not mean the runner died. Governs R16, R17. (session-settled: user-approved — chosen over reaping by timestamp at once and over sending every running workflow back to the queue.)

### Scope Boundaries

- The runner's retries during an attempt, and the leases they keep, are part 6's.

## Planning Contract

### Key Technical Decisions

- KTD11. **`fromConnect` maps to `ErrUnavailable` only what means the engine is gone.** That is a non-connect error, a non-remote `CodeUnavailable`, and a cut stream's incomplete envelope. Other non-remote errors, such as a 403 from the Host check, a 404 from a wrong URL, or a marshal failure, become `errServer`, with their cause kept, and are not retried by `next` or `run`. Every path that returns `ErrUnavailable` checks the caller's context first, including `Follow`'s early end of stream.

### U2. Unreachable means unreachable

**Goal:** only an engine that is gone reads as `ErrUnavailable`, so the runner's and `run`'s retries never loop on a wrong address.

**Requirements:** R17; KTD11.

**Dependencies:** none.

**Files:**
- Modify `internal/transport/connect/errors.go` and `internal/transport/connect/client.go`.
- Test in `internal/transport/connect/client_test.go`.

**Approach:**
1. In `fromConnect`, keep `ErrUnavailable` for a non-connect error, a non-remote `CodeUnavailable`, and the incomplete envelope of a cut stream. Send any other non-remote error to `errServer`, keeping its cause.
2. In `Follow`'s early end of stream, check the context before returning `ErrUnavailable`.

**Patterns to follow:** the cases listed in `docs/solutions/best-practices/connect-go-non-remote-error-does-not-mean-the-server-is-unreachable.md`.

**Test scenarios:**
- A client whose base URL is `http://0.0.0.0:<port>`, refused by the Host check, gets an error that is not `ErrUnavailable`.
- A client against a path that answers 404 gets an error that is not `ErrUnavailable`.
- `TestClosedServerIsUnavailable` and `TestFollowCutByServerIsUnavailable` stay green.
- A `Follow` whose context is cancelled as the stream ends early returns the context's error.

**Verification:** the scenarios pass, and `runner.next` gives up on a 403 instead of retrying it.
