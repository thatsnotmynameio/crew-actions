## Planning Contract

### Key Technical Decisions

- KTD7. **A step's log is `<log dir>/<database id>/<attempt id>/<position>.log`, created when the step starts and appended to by offset.**
  - Migration `00002` stores a random id in a one-row table, so a reset database never reuses an old build's files.
  - Once `StartStep` has committed, the engine creates the file if it is absent, never truncating it, so a file exists only for a step that really started.
  - `log` only appends to an existing file, under one lock per file, and writes before it answers. Bytes below the file's size are acknowledged and dropped; bytes past it are appended; an offset beyond the size is refused as `ErrInvalid`. The answer is always the size held.
  - The runner checks that every answer equals its offset plus its data's length, and treats anything else as a failed call.

  Rejected: naming files by ids alone, which shows an old build's output after a database reset with no error. Rejected: creating the file exclusively inside the step's transaction, which leaves a file for a step that never started when the commit fails, and blocks that step's start for good.

### High-Level Technical Design

What `log` does with a chunk at `offset` of length `n` when the file holds `size` bytes (KTD7):

| Case | Written | Answer |
|---|---|---|
| `offset + n <= size` | nothing | `size` |
| `offset <= size < offset + n` | the bytes past `size` | `offset + n` |
| `offset > size` | nothing | `ErrInvalid` |
| no file for that step | nothing | `ErrInvalid` |

## Implementation Units

### U4. Logs on disk

**Goal:** a step's output is appended by offset to one file per step and attempt, and a resent chunk is never written twice.

**Requirements:** R21; KTD7.

**Dependencies:** none.

**Files:**
- Create `internal/store/logs/logs.go` and `internal/store/logs/logs_test.go`.

**Approach:**
- `logs.Dir` is rooted at the log directory joined with the database id. It offers create if absent, append at offset, size, and read from an offset up to a limit, each keyed by attempt id and position.
- Paths are built only from the integer ids, so no input names a path.
- One mutex per file, held in a map, serializes the size check and the append.
- Directories are created with 0700 and files with 0600.

**Test scenarios:**
- Create, then append 10 bytes at 0: size 10, and the content reads back.
- Resend the same 10 bytes at 0: answer 10, and the file is unchanged.
- A chunk at offset 5 with 10 bytes after 10 are held: only the last 5 are written, and the answer is 15.
- A chunk at offset 20 when 15 are held: `ErrInvalid`, and nothing is written.
- Append without create: `ErrInvalid`. Create on a file that holds bytes leaves them in place.
- Two goroutines appending the same chunk at once: the file holds it once (run with `-race`).
- Reading from an offset returns at most the limit, and an empty read at the end.
- Size and read on a step with no file return 0 bytes and no error.

**Verification:** the scenarios pass under the race detector.
