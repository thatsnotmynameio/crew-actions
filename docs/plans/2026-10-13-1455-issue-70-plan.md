## Planning Contract

### Key Technical Decisions

- KTD3. **The stored definition is the compiled workflow, encoded as the protocol's `Workflow` message.** The engine runs `spec.Parse` once, at submit, which is where R8's refusal happens. It stores the name and resolved steps that `next` hands out and `accept` takes the step names from, as `model.Workflow.Definition`'s comment and the first migration already describe. Rejected: storing the file and parsing it again at hand-out, where a file a newer parser refuses would roll back the hand-out and stall the queue behind the oldest pending workflow.
- KTD7. **A step's log is `<log dir>/<database id>/<attempt id>/<position>.log`, created when the step starts and appended to by offset.**
  - Migration `00002` stores a random id in a one-row table, so a reset database never reuses an old build's files.
  - Once `StartStep` has committed, the engine creates the file if it is absent, never truncating it, so a file exists only for a step that really started.
  - `log` only appends to an existing file, under one lock per file, and writes before it answers. Bytes below the file's size are acknowledged and dropped; bytes past it are appended; an offset beyond the size is refused as `ErrInvalid`. The answer is always the size held.
  - The runner checks that every answer equals its offset plus its data's length, and treats anything else as a failed call.

  Rejected: naming files by ids alone, which shows an old build's output after a database reset with no error. Rejected: creating the file exclusively inside the step's transaction, which leaves a file for a step that never started when the commit fails, and blocks that step's start for good.
- KTD16. **Tests that need Postgres outside the store get a database of their own.** `go test ./...` runs packages in parallel, and the store's tests empty the shared database's tables. A new `internal/store/postgres/postgrestest` package creates each test's database from a migrated template on the server `CREW_ACTIONS_TEST_DATABASE_URL` names, drops it at cleanup, and skips without the variable. depguard's `postgres-users` entry that denies `internal/store/postgres/` subpackages narrows to `internal/store/postgres/queries`, which is what its description names, so tests elsewhere can import `postgrestest`. Rejected: pgtestdb, which architecture section 6 lists, because one `CREATE DATABASE … TEMPLATE` does the same without a test-only module (D19's reason).

## Implementation Units

### U3. Database identity, attempt lookup, test databases

**Goal:** the engine can name its log directory after the database, find an attempt's workflow and build, and test against a database of its own.

**Requirements:** R21; KTD7, KTD16.

**Dependencies:** none.

**Files:**
- Create `internal/store/postgres/migrations/00002_database_identity.sql` and `internal/store/postgres/identity.go`.
- Modify `internal/store/postgres/queries.sql`, regenerate `internal/store/postgres/queries/`, and modify `internal/store/postgres/attempts.go`.
- Create `internal/store/postgres/postgrestest/postgrestest.go`.
- Modify `internal/store/postgres/builds.go` and `.golangci.yml`.
- Create `internal/store/postgres/identity_test.go`, and extend `internal/store/postgres/attempts_test.go`, `internal/store/postgres/builds_test.go` and `internal/store/postgres/migrate_test.go`.

**Approach:**
- The migration creates a one-row table holding a random UUID (`gen_random_uuid()`), with a constraint that keeps it one row. `DatabaseID` reads it.
- A new primitive returns an attempt's workflow id, build id and number, or `ErrNotFound`.
- A new primitive returns a workflow's definition by id, or `ErrNotFound`, for `accept` (KTD3).
- `GetBuild` reads in one read-only `REPEATABLE READ` transaction, so its states agree (KTD9).
- `.golangci.yml`'s `postgres-users` entry narrows as KTD16 says.
- `postgrestest.New(t)` opens the server from `CREW_ACTIONS_TEST_DATABASE_URL`, creates each test's database from a template and drops it with `FORCE` at cleanup. The template is named after a hash of the embedded migrations and created only when absent, under a server-wide advisory lock that is held until every connection to the template is closed, so parallel test binaries share it and a changed migration gets a new one. Each clone gets a fresh database id. Without the variable it skips with the message the store's tests use.
- The store's `newStore` truncate list leaves the identity table alone.

**Patterns to follow:** `emptyDatabase` and `requireDatabase` in `internal/store/postgres/main_test.go`; the sqlc command recorded in `sqlc.yaml`.

**Test scenarios:**
- After `Migrate`, `DatabaseID` returns a UUID, the same on a second call, and a different one on another fresh database.
- A second insert into the identity table fails.
- The lookup returns the workflow, build and attempt number of an attempt started through `StartAttempt`, and `ErrNotFound` for an unknown id.
- The workflow lookup returns the definition `CreateBuild` stored, and `ErrNotFound` for an unknown id.
- Two `postgrestest.New` databases are independent: a build created in one is not found in the other, and their `DatabaseID`s differ.
- `GetBuild` inside an outer `InTx` still joins it, and alone returns the same snapshot as before.

**Verification:** the scenarios pass with the test database, skip without it, the sqlc command leaves `queries/` unchanged, and lint passes with the narrowed rule.
