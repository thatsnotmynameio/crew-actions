## Implementation Units

### U1. Refuse unimplemented keys

**Goal:** a file with a key slice 0 does not implement is refused with an error that names it as not supported yet, and any other stray key as unknown.

**Requirements:** R8; KTD14. Covers AE6 at the parser.

**Dependencies:** none.

**Files:**
- Modify `internal/spec/spec.go` and `internal/spec/spec_test.go`.

**Approach:**
- `fields` resolves each key through `resolve` and refuses a key that is not a scalar, before it checks the allowed set.
- The known keys per level are package constants: the workflow's six and a step's `when`.
- A new exported error type names the key, its path and line, and reads "not supported yet".
- The existing test that expects `depends_on` as an unknown key moves to the new type.

**Patterns to follow:** `*KeyError` and the table in `TestParseRefusesKeys`.

**Test scenarios:**
- Covers AE6. `depends_on: [build]` at the top level gives the new error, naming `depends_on` and its line.
- Each of `when`, `queue`, `labels`, `image` and `settings` at the top level, and `when` on a step, gives the new error with its path (`steps[1].when`).
- `comands` on a step, and `retry` at the top level, give `*KeyError` (unknown).
- A key written as an alias whose anchor is the string `depends_on` gives the new error. An alias key pointing at a mapping is refused as not a scalar.
- A valid file still parses to the same `Workflow`.

**Verification:** the scenarios pass, and `internal/spec` still passes the `pure` depguard rule.
