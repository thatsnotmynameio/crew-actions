## Product Contract

### Summary

A flag parser for the repository's identity that never leaks a credential, plus `ErrInvalid`, with a constructor that wraps a showable message, and `ErrUnavailable`, beside `ErrConflict` and `ErrNotFound`.

### Context

The identity is how `run` names a build's repository, and the sentinels are the one error vocabulary every later part branches on. This part builds some of R9, which part 11 completes. In text copied from #22, "part 5", "part 6" and "part 7" are parts of #4, not of this split.

### Key Decisions

- **The repository's identity is host, organization and repository, parsed once from a URL; the URL is not kept.** Revises the architecture's "organization and repository on every row" by adding the host. Governs R9, R10. (session-settled: user-directed — chosen over organization and repository alone, since two hosts can share names, and over storing the URL, since one repository has several URLs and a URL can carry a credential.)

### Acceptance Examples

- AE8. **Covers R9, R10.** Given an `origin` of `https://user:token@gitlab.com/group/sub/repo.git`, then the build's identity is host `gitlab.com`, organization `group/sub`, repository `repo`, and the token is stored nowhere; given a directory outside git and no `--repo`, `run` refuses.

### Scope Boundaries

- This part covers AE8 at the parser only; reading `origin` through git and refusing outside a repository are part 11's.
- The transport's mapping of the sentinels to connect codes is part 8's.

## Planning Contract

### Key Technical Decisions

- KTD4. **Errors cross HTTP as a small vocabulary of `internal/model` sentinels.** The engine returns `ErrConflict`, `ErrNotFound`, a new `ErrInvalid`, which wraps a message that is safe to show, or a new `ErrUnavailable` when it is stopping. `transport/connect` maps them to `Aborted`, `NotFound`, `InvalidArgument` and `Unavailable`, and back. A request over the size limit (`ResourceExhausted`) comes back as `ErrInvalid`. A non-remote error, such as a refused connection or a stream cut by a dying server, also comes back as `ErrUnavailable`. Any other error reaches the client as `Unknown` with no message, so internal detail never leaks. When the caller's own context is done, the client returns the context's error, never `ErrUnavailable`, so a Ctrl-C is never retried. The runner and `run` branch on these sentinels with `errors.Is` and never see a connect code.

### Assumptions

These are inferred, unconfirmed bets.

- Every message `ErrInvalid` carries is safe to show to the submitter: spec errors name a key, a path and a line, and YAML syntax errors may quote the file, which only its submitter sees.

## Implementation Units

### U2. `--repo` identity and error sentinels

**Goal:** `--repo` accepts `host/organization/repository` as well as a URL, and the model has the sentinels the transport maps (KTD4).

**Requirements:** R9; KTD4. Covers AE8 at the parser.

**Dependencies:** none.

**Files:**
- Modify `internal/model/repository.go`, `internal/model/repository_test.go` and `internal/model/errors.go`.
- Create `internal/model/errors_test.go`.

**Approach:**
- A new parser for the flag tries `ParseRepository` when the value has a scheme or the scp form, and otherwise splits it on `/`: the first part is the host, the last the repository, and the rest the organization. Every part, the host included, is refused when it holds `@` or `:`. `ParseRepository` keeps refusing a bare path, since an `origin` that is a local path is not a remote.
- `ErrInvalid` comes with a constructor that wraps a showable message, and `ErrUnavailable` joins `ErrConflict` and `ErrNotFound`.

**Patterns to follow:** `repository_test.go`'s map of cases and its `secret` constant: no error repeats the input.

**Test scenarios:**
- `gitlab.com/group/sub/repo` gives host `gitlab.com`, organization `group/sub`, repository `repo`.
- `github.com/org/repo` gives one organization level.
- `https://user:token@gitlab.com/group/sub/repo.git` through the flag parser gives the same identity as `ParseRepository`, and the error for a bad value never contains `token`.
- `host/repo`, a leading `/`, an empty part and whitespace are refused.
- `token@github.com/org/repo` is refused, and the error does not contain `token`.
- An error made with `ErrInvalid` matches it with `errors.Is` and shows its message.

**Verification:** the scenarios pass, and `internal/model` still passes the `pure` rule.
