## Product Contract

### Summary

A template helper shared by `postgrestest` and the store's in-package tests, so every store test runs on a database of its own.

### Context

The lease work of later parts adds races the store's tests must run in parallel on fresh workflows; a shared database that each test empties gets in their way. This part builds some of R26 ("The store's tests run against a real Postgres, one database per test from a migrated template, and skip when `CREW_ACTIONS_TEST_DATABASE_URL` is unset"), which part 7 completes with the end-to-end test of a lost runner.

## Planning Contract

### Key Technical Decisions

- KTD14. **The store's tests and `postgrestest` share one template helper, in a package that does not import the store.** The template logic moves to `internal/store/postgres/internal/testdb`, which takes a migrate function. `postgrestest` wraps it with `postgres`'s migrations, and the store's in-package tests call it with their own. ### U1. One database per store test

**Goal:** the store's own tests each get a migrated database copied from the shared template, like every other package's.

**Requirements:** R26; KTD14.

**Dependencies:** none.

**Files:**
- Create `internal/store/postgres/internal/testdb/testdb.go`.
- Modify `internal/store/postgres/postgrestest/postgrestest.go` to wrap it.
- Modify `internal/store/postgres/main_test.go` and the store's `*_test.go` helpers (`newStore`, `requireDatabase`).
- Modify `AGENTS.md` if the store's tests no longer empty shared tables.

**Approach:**
1. Move the template and copy logic from `postgrestest` to `testdb`, which takes a migrate function and imports pgx but not `postgres`.
2. `postgrestest.New` keeps its signature and calls `testdb` with `postgres`'s migrations.
3. `newStore(t)` opens a store on a `testdb` copy, and `TRUNCATE` goes away. `TestMain` stops migrating the shared database. Tests that need bare databases (`migrate_test.go`) keep making them.

**Patterns to follow:** `postgrestest.go` as it is, and `docs/solutions/best-practices/test-template-database-reused-only-once-marked-finished.md`.

**Test scenarios:**
- Two store tests that each insert a build, run in parallel, each see only their own.
- Without `CREW_ACTIONS_TEST_DATABASE_URL`, the store's tests skip and name the variable.
- `postgrestest.New` still gives a database with a database id of its own.

**Verification:** the store's tests pass with `-count=1` on a fresh server, and `go vet` finds no import cycle.
