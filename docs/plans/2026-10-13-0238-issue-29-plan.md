## Planning Contract

### Key Technical Decisions

- KTD11. **The URL parser lives in `internal/model` and never repeats its input in an error.** The `run` client (part 4) cannot import the store, and the parser does no I/O. Errors from Go's `url.Parse` quote the whole URL, credential included, so the parser builds its own error messages, which name only the problem.

### Assumptions

These are bets nobody confirmed (headless run). Each one is recorded so a reviewer can overturn it.

- **The identity drops the port, lowercases the host, and keeps the case of the organization and the repository.** The HTTPS and SSH URLs of one repository then give one identity. Case variants on a case-insensitive forge, SSH host aliases, and forges whose SSH and HTTPS paths differ give separate identities, and `--repo` (part 4) is the way out.
- **Scp-like remotes (`git@host:org/repo.git`) are parsed as git reads them:** no `://`, and a `:` before the first `/`. `file://` URLs, local paths and URLs with no organization are refused. Query strings and fragments are dropped.
- **The `host/organization/repository` shorthand of `--repo` is not parsed here.** R9 belongs to part 4, which can add the shorthand to the same parser.

### Sequencing

U2 is the only unit. It needs part 1's `internal/model` package, not its types.

## Implementation Units

### U2. Repository identity parser

**Goal:** a repository URL becomes host, organization and repository once, without the credential ever being kept or printed.

**Requirements:** R10; KTD11.

**Dependencies:** none.

**Files:**
- Create `internal/model/repository.go` and `internal/model/repository_test.go`.

**Approach:**
- A `Repository` value has host, organization and name. Its string form is `host/organization/name`, the value later parts use as `crew.repository`.
- Order of work:
  1. Detect the scp-like form before calling `url.Parse` (see Assumptions).
  2. Accept the `https`, `http`, `ssh`, `git+ssh` and `git` schemes.
  3. Drop the userinfo, port, query and fragment, then lowercase the host.
  4. Strip trailing slashes, then one `.git` suffix.
  5. Split the path. The last segment is the repository, and everything before it is the organization.
- Refuse an empty host, a missing organization, empty or `.`/`..` segments, whitespace or control characters, and `file://` or local paths.
- Error messages name the problem only, and never wrap `url.Parse`'s error (KTD11).

**Test scenarios:**
- `https://user:token@gitlab.com/group/sub/repo.git` gives `gitlab.com`, `group/sub`, `repo` (the parsing half of the parent's AE8).
- `git@github.com:thatsnotmynameio/crew-actions.git` and `https://github.com/thatsnotmynameio/crew-actions` give the same identity.
- `ssh://git@GitHub.com:22/org/repo.git/` gives host `github.com`, organization `org`, repository `repo`.
- `git://host/org/repo`, `http://host/org/repo` and `git+ssh://git@host/org/repo.git` each parse.
- `https://host/org/repo.git?private_token=x#frag` drops the query and the fragment.
- `https://host/repo.git` (no organization), `https://host/org//repo`, `https://host/org/../repo`, `file:///srv/repo.git`, `/srv/repo` and `../repo` are refused.
- For a token-bearing input that fails on each refusal branch, including a malformed percent escape (`https://user:tok%zz@host/org/repo`), the error text never contains the token.

**Verification:** every case above passes, and no error path formats the raw input.
